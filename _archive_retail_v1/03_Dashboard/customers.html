Who the transactions belong to

Revenue steps down from $566k in the 18-29 band to $468k at 60-plus, a slope well inside what random assignment produces.

■
CustomerID is not a usable key, so there are no customers on this page. The file carries 631 distinct CustomerID values, and 258 of them appear on rows with conflicting age, gender or city — the same ID is one age, gender and city on one row and a different age, gender and city on another. An ID that changes its own demographics cannot identify a person. Everything below therefore describes the demographic attributes of transactions, not of customers. No customer count, no repeat-purchase rate, no churn and no lifetime value can be computed from this data, and none is shown. Every percentage here is a share of revenue across rows.

▲
The age bands fall in a tidy descending order, and that order is not a finding. The distance from the highest band to the lowest is about 4 points of total revenue, and the spread across the five bands tests as no signal (chi-square p = 0.44) — a gap this size appears routinely when 1,000 rows are assigned to five buckets at random. Read the totals. Do not read the ranking as an instruction, and do not move a budget toward a band because it sits at the top of this chart.

Age band by transaction count and average transaction value

An age-band × product-category cross-tab is not available: the live data contract publishes the category matrix against city only, so no age × category cell exists to show. What can be shown honestly is volume against size — transactions per band, and the average value of one transaction (revenue ÷ transactions) inside it.

Average transaction value sits in a narrow band around the $2,562 all-rows average, and the same caution applies to these columns as to the chart above. Revenue is uncorrelated with quantity in this file, so an average here is a per-row arithmetic mean, never a basket value.

What this page supports: a description of the transaction mix — how revenue distributes across the age and gender recorded on each row. What it cannot support: any statement about people. Customer counts, loyalty, repeat rate and segment value all need a stable key, and this file does not have one.
